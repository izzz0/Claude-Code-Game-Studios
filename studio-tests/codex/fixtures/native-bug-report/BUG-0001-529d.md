## Reproduction Steps
**Preconditions**: Run a build containing the inspected `src/game.gd` in the one-screen courier scene. Three targets are available: Target Alpha (0), Target Beta (1), and Target Gamma (2).

1. Start the courier scene and collect Target Alpha at index 0.
2. Collect Target Beta at index 1.
3. Move the player to Target Gamma, the third target at index 2.
4. Trigger collection so the delivery system calls `collect_target(2)`.
5. Repeat the collection attempt at Target Gamma and inspect the guard's return value and delivery state.

**Expected Result**: Collection of the valid third target is accepted and Target Gamma is recorded as delivered, satisfying STORY-001 AC-3.

**Actual Result**: Collection is rejected every time and the third target is not recorded as delivered, according to the author. In the inspected source, `collect_target(2)` takes the guard branch and returns `false`.

## Technical Context
- **Affected file**: `src/game.gd`, lines 3–8; collection guard at lines 6–7.
- **Related systems**: Delivery progress and all-three-parcels completion, as described by `production/epics/courier/EPIC.md` and `production/epics/courier/story-001-delivery.md`.
- **Possible root cause**: The target array contains three entries, with Target Gamma at index 2. The hard-coded guard `if target_index >= 2:` rejects that valid index before the success return. This explains the reported rejection by source inspection. The supplied script contains no delivery-recording logic, so that downstream state was not independently inspected.

```gdscript

func collect_target(target_index: int) -> bool:

        return false # BUG: third target is index 2
    return true
```
